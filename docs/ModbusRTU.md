# ModbusRTUとは

工場の装置どうしをつなぐ、昔からある通信ルール（プロトコル）です。単純で壊れにくいため、計測機器では今でも定番です。

## 3つだけ覚えれば動かせる

**① マスタとスレーブ**

必ず「マスタが聞いて、スレーブが答える」形。スレーブから勝手に喋ることはありません。

本システムでは **PCのブラウザ＝マスタ**、**Arduino Nano R4＝スレーブ（ID=1）** です。

**② レジスタ**

やり取りするデータは、番号付きの16bitの箱（レジスタ）に入っています。番号を指定して読み書きするだけです。

**③ RTUモード**

データをそのままバイナリで流し、末尾にCRC（誤り検出用の符号）を付ける方式です。文字列で送るASCIIモードより短く速く、化けたら捨てられます。

## 本システムの通信仕様

| 項目 | 値 |
| --- | --- |
| 接続 | USB（CDCシリアル） |
| 速度 | 38400bps |
| スレーブID | 1 |

## レジスタ割り当て

| 種類 | 番号 | 中身 | 型 |
| --- | --- | --- | --- |
| 入力レジスタ（読み取り専用） | 0〜15 | アナログ入力 AI0〜AI15 | int16_t |
| ホールディングレジスタ（読み書き） | 0〜7 | アナログ出力 AO0〜AO7（mV） | uint16_t |

AO に `5000` を書けば 5.000V が出る、という素直な対応です。

## 通信の中身（雰囲気だけ）

```
マスタ →  01 04 0000 0010 <CRC>     スレーブ1番、入力レジスタ0番から16個ちょうだい
スレーブ → 01 04 20 .... <CRC>      はい32バイト（16レジスタ分）
```

`04` などの番号は「ファンクションコード」＝命令の種類です。ライブラリが組み立ててくれるので、手で書くことはありません。

## Modbusには3つの姿がある

「Modbus」と一口に言っても、**運び方が3種類**あります。中身（レジスタ番号やファンクションコード）はどれも同じで、包み方だけが違います。

| | Modbus **RTU** | Modbus **ASCII** | Modbus **TCP** |
| --- | --- | --- | --- |
| 通信路 | シリアル（RS-485/232、USB） | シリアル | Ethernet（LAN） |
| データ形式 | バイナリのまま | 16進数を**文字**で送る | バイナリのまま |
| 誤り検出 | CRC16 | LRC（簡易） | なし（TCPが保証） |
| 区切り | 一定時間の無音（3.5文字分） | `:` で始まり改行で終わる | ヘッダに長さが入る |
| 通信量 | 少ない | **約2倍**（遅い） | 中 |
| 相手の指定 | スレーブID | スレーブID | IPアドレス＋ポート502 |

- **RTU**：いちばん普及している定番。速くて短い。ただし「無音で区切る」ため、タイミングにシビア
- **ASCII**：人が読める形なので、通信内容を目で追える。タイミングが緩いので古い機器や電話回線越しで使われた。今は少数派
- **TCP**：LANに繋ぐだけで届く。複数のマスタから同時にアクセスできる。工場のPLCではこれが主流

> 🔰 このほか「Modbus RTU over TCP」（RTUの中身をそのままLANで流す方式）もあります。名前が紛らわしいので、機器を選ぶときは仕様書の表記をよく確認してください。

## なぜ本システムはRTUなのか

- USBケーブル1本で完結する。LAN配線もIPアドレス設定も要らない
- ブラウザの Web Serial API から直接シリアルを叩けるので、**間にサーバーを立てる必要がない**
- 相手は1台だけなので、TCPの同時接続性は不要

USB経由なので、実際は [USB CDC](./USBCDC.md) の上をRTUのフレームが流れています。

## 初心者向けの注意

- 1本の線に同じIDのスレーブを2台つなぐと壊れます（本システムは1台なので気にしなくてOK）
- 応答がない＝ボーレート・ID・ポートのどれかが違う、が定番の原因です
- COMポートは同時に1つのソフトしか開けません。Arduino IDEのシリアルモニタを閉じてから計測アプリを開いてください
