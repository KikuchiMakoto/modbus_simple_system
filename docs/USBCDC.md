# USB CDC ACMとは

**USB機器をCOMポート（シリアルポート）に見せるための標準規格**です。CDC＝Communication Device Class、ACM＝Abstract Control Model。

PCから見れば普通のCOMポートですが、中身の作りは従来のArduinoと根本的に違います。

## 変換ICを挟む方式との違い

```
従来のNanoなど： PC ──USB── [変換IC CH340/FT232] ──UART── マイコン
Arduino Nano R4： PC ──USB────────────────────────────── マイコン
```

| | USBシリアル変換IC | ネイティブUSB（CDC ACM） |
| --- | --- | --- |
| ボーレート設定 | 変換ICとマイコンの間で**実際に効く** | **形式だけ**。実効速度はUSB次第で桁違いに速い |
| ドライバ | 機種によっては追加インストールが必要 | OS標準（標準クラスなので挿すだけ） |
| 遅延 | 変換ICのバッファ分の遅れがある | ほぼ無し |
| ポートを開くと | **マイコンがリセットされる** | リセットされない |
| スケッチが止まると | ポートは生きている（別チップだから） | **ポートごと消える** |

## 書き込み時のリセットの仕掛け

**従来型**：PCがDTR信号を下げる → コンデンサ経由でRESETピンが引かれる → ブートローダが起動。
この副作用で、**シリアルモニタを開くたびにマイコンがリセット**され、計測中なら値が最初からやり直しになります。

**ネイティブUSB**：DTRを操作してもリセットは掛かりません。代わりに **「1200bpsでポートを開いてすぐ閉じる」（1200bps touch）** という合図でブートローダに落ちます。Arduino IDEや書き込みツールが自動でやってくれるので、意識する必要はありません。

> 🔰 [ArduinoNanoR4](./ArduinoNanoR4.md) で「計測アプリを開き直しても値が飛ばない」のは、この仕組みのおかげです。

## 本システムでの意味

- ファームウェアの **38400bps は Modbusの仕様上の表記**で、CDCでは速度の上限にはなりません。実効速度はUSB側で決まるので、ポーリングが速くても詰まりません
- ブラウザの Web Serial API からは、ごく普通のCOMポートとして見えます
- ドライバのインストールが不要。挿せばポートが現れます

## 注意

- **ポートが消えた ＝ ファームウェアが止まっているか、リセット中**のサインです。ケーブルを疑う前にこちらを疑ってください
- 書き込みに失敗し続けるときは、リセットボタンを素早く2回押してブートローダに入れる方法が使える場合があります
- COMポートは同時に1つのソフトしか開けません。Arduino IDEのシリアルモニタを閉じてから計測アプリを開いてください
